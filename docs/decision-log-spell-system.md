**2026-08-19 (new session, `anavale-wiki-spells-table` branch — Class tab Spells Learned table: row-height fix + search/filter/favorite) — `sheet/index.html`, new `character_sheet.favorite_spells` column.**
Two asks, both matching real `requests` rows (`c0ef5099`/`b49be3b5`, area `wiki-backlog`, now `done`).
**1 — Row height, real root cause found via D2, not the first theory tried.** Investigated the CSS first (checked `.cs-inv-table { table-layout: auto }`, the `.cs-sl-table` nth-child width rules) and confirmed live via `getBoundingClientRect()` that the Description column genuinely does get squeezed hard on narrower viewports (292px wide at 1280px window down to 128px at 950px) — real, but that's not what was making even *short* descriptions blow up. Built a line-clamp fix (`.cs-sl-desc { -webkit-line-clamp: 3 }` + a "Show more"/"Show less" toggle, `applySpellDescClamp()` measuring `scrollHeight > clientHeight` per row) and found the toggle never showed, on any row, regardless of real overflow. First theory — a `-webkit-line-clamp` synchronous-read timing issue — led to trying `requestAnimationFrame`, which flat-out never fired in this session's own Browser-pane tooling (confirmed via a bare `window.__rafFired` marker test, still `false` after a full 2s real wait) while a bare `setTimeout` marker fired correctly in the same tab — a real, verified difference, not assumed. Switching to `setTimeout(fn, 0)` still didn't fix it. That contradiction (a timer confirmed to fire, but the measurement inside it still wrong) was the actual clue: rechecked with `ACTIVE_TAB` logged alongside the measurement and found the real cause — `renderSpellsLearnedTable()` runs at boot while the Class tab's `.cs-tab-content` wrapper is still `[hidden]` (Your Story is the default active tab, per `updateTabUI()`'s `el.hidden = el.dataset.tabContent !== ACTIVE_TAB`), and an element under `display:none` always reports `scrollHeight===clientHeight===0` — so the overflow check was reading "nothing overflows" for every row, from the very first render, and no amount of deferral fixes that since the tab is *still* hidden a frame (or a full second) later too. Fixed at the actual cause: `setActiveTab()` now re-runs `applySpellDescClamp()` whenever `tabKey === 'class'`, the one action that makes the table visible for the first time; `renderSpellsLearnedTable()` itself calls the sweep directly (no deferral needed) for the case of a re-render while the tab is *already* visible (e.g. toggling Prepared/Favorite while looking at the table). Row height is now bounded to a real 3-line clamp regardless of column squeeze — confirmed via live measurement that a row with genuine short content (e.g. Guidance, 183 chars) shows its toggle only when the column is actually narrow enough to truncate it, and stays untouched at desktop widths where it fits.
**2 — Search + filter + favorite, scoped to the learned list only.** DM's ask was explicit that this isn't a spell browser — Round 2 Revisions (2026-08-17) had removed the DM-assignment-only table's search/filter row entirely on the reasoning that a short 5-15-item list didn't need it; that call is directly reversed here, not silently re-litigated, since known lists grow past level 1 and the DM asked for it back. Level filter is a static Cantrip/1-9 enum (spell levels are a fixed domain regardless of what one character knows, same reasoning as Inventory's own static Category select) rather than derived from the learned list. Favorite: new `character_sheet.favorite_spells` (`text[]`, same shape/insert-default convention as `attuned_items`/`learned_spells`/`prepared_spells` — confirmed via `information_schema` no such column or equivalent existed before adding it) backing a small star button embedded in the Name cell (not a new table column, which would have meant renumbering every nth-child width rule for one icon) — `toggleSpellFavorite(id)` mirrors `unprepareSpell()`'s exact read-mutate-save-rerender shape.
